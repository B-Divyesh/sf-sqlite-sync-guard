● A local SQLite safety check

Check SQLite files before folder sync

For developers syncing folders between computers, it finds unsafe files and creates a verified transfer backup.

Try it with sample dataSee a live database scan and safe export.
  • Free.
  • Runs locally.
  • No telemetry.
Prevents unsafe copies; does not sync database changes.Never open the same writable database from two synced computers.

01 / Check the files

See whether files are safe to copy

The scan warns when a database has journal files or is in active use. Its exit code works in scripts.

02 / Make the transfer

Create a verified transfer backup

SQLite’s backup function captures committed data. The tool checks the new backup before publishing it.

  1. 1
    Back up

    Capture one consistent point in time.

  2. 2
    Check

    Verify the database and calculate its SHA-256 checksum.

  3. 3
    Transfer

    Copy the transfer backup and its manifest.

03 / Use the tool

Scan, export, or add ignore rules

Read-only check

Scan a synced folder

sqlite-sync-guard scan ~/Sync

Reports database journal files and active use without changing the database.

Explicit write

Export a transfer backup

sqlite-sync-guard export app.db -o ./transfer

Writes a checked .backup.sqlite3 and a manifest with its checksum.

Ignore rules

Keep live files out of sync

sqlite-sync-guard ignore ~/Sync --client syncthing

Preserves other rules. Running it again leaves the file unchanged.

{ }

Use JSON in scripts

Put --json before or after a command. Scan exits 0 when safe, 2 when unsafe, and 1 on error.
